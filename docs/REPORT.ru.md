# OpenFlux Desktop: анализ и план

## 1. Что представляет собой OpenFluxDesktop сейчас

`C:\Users\meepo\IdeaProjects\OpenFluxDesktop` — KMP-проект с одним таргетом `jvm()`: модули `shared` и `desktopApp`. Compose Multiplatform 1.11.1, Material3 1.11.0-alpha07, Kotlin 2.4.10, Gradle 9.1.

- **Навигация**: `androidx.navigation` (`NavHost` + `Destination`). Voyager не используется. Экраны: `Welcome` → `Transport` (выбор из 4 транспортов) → `ConnectionConfig`.
- **Состояние**: глобальный синглтон `UiState` с `mutableStateOf`. Настройки берутся из переменных окружения и не сохраняются между запусками. Профилей нет.
- **Бизнес-логика**: `BackendManager` запускает ядро `openflux` через `ProcessBuilder`. Статус «подключено» и скорость определяются разбором отладочного лога по строкам `<-`/`->` и фразам вроде «WS connected». `BinaryDownloader` скачивает ядро из релизов p1neappleXpress. `CaptchaBrowser` открывает капчу в Edge и забирает cookies через DevTools. `CaptchaIpc` получает запросы капчи от ядра через Unix-сокет.
- **UI**: `ConnectionConfigScreen.kt` на 872 строки объединяет форму, кнопку, лог, статистику и диалоги. Тема `FluxColors` (неоновый cyan на тёмно-синем) визуально не связана с Android. Окно 1100×800 с `resizable = false`.
- **Тесты**: 3 JVM-теста (сборка аргументов, cookies из DevTools, IPC-кодек).

**Что работает**: запуск клиента и выходной ноды через CLI, загрузка ядра, капча через Edge, QR для Cups.

**Частично**: статистика (зависит от `--debug` и формата лога); выходная нода (QR только для Cups).

**Сломано или временно**: `resizable = false`; настройки теряются при перезапуске; JVM-код (`java.io.File`, `ProcessBuilder`) лежит в `commonMain`; `ConnectionStatus.kt` пустой; «подключено» определяется по подстрокам лога; комментарии на смеси русского и английского; `Platform.kt` — заготовка из шаблона.

**Дублирование**: ручные карточки, поля и пилюли повторяются внутри экрана; цвета размазаны по файлам.

**Что мешает развитию**: нет модели профиля, нет слоя хранения, UI вызывает `BackendManager` напрямую, состояние — набор boolean (`isRunning`, `isConnected`, `error`, `exitCode`), из которых можно собрать невозможные комбинации.

## 2. Как устроен Android OpenFlux

Референс — текущее приложение 1.2.3 (форк damnurmum/OpenFlux-Android с мастером нод). Java, UI строится программно в одном `MainActivity` (4 тысячи строк), ядро подключено через gomobile (`io.openflux.bridge.mobile.Mobile`).

- **Разделы** (плавающая «таблетка» внизу): Главная, Профили, Логи, Настройки.
- **Главная**: большая круглая кнопка 140 dp с двумя кольцами (200 и 170 dp) и пульсирующей волной. Внутри кнопки иконка питания, статус, аптайм и скорость. Цвет по состоянию: простой — surface; подключено — `#4F7CFF`; переходные состояния — `#FBBF24`; ошибка — `#EF4444`. Ниже строка выбранного профиля и карточка «Активные параметры» (строки «ключ — значение» с разделителями). В режиме выходной ноды — карточка с QR.
- **Профили**: список в карточке, у строки значок, название и сводка транспортов. В шапке кнопки «QR», «+», «Создать свою ноду». Редактор: название, значок из 10, режим (обычный или Session), транспорт (Yandex Docs, Volga, Boards, Mail.ru, Cups, MAX, direct), кодек, URL, ключ с генерацией, дополнительные транспорты Session с приоритетами.
- **Импорт**: `openflux://v1/…` (deflate + base64url JSON), QR-сканер, ссылка из чата.
- **Логи**: моноширинный текст в карточке, подсветка тегов, очистка, скрытие URL.
- **Настройки**: сгруппированный список (значок в «пузыре», заголовок, описание, шеврон), каждый пункт открывает свой экран: Режим работы (туннель / SOCKS5 / выходная нода; порт, доступ из LAN, пароль), Сеть (DNS, MTU), Приложения (белый и чёрный списки), Маршрутизация (пресеты доменов в обход), Вид (тема, автопрокрутка, чувствительные данные в логах, анимации), О проекте.
- **Дизайн-язык**:
  - светлая тема: фон `#F8F9FA`, surface `#FFFFFF`, текст `#202124`, вторичный `#5F6368`, граница `#DADCE0`, акцент `#4F7CFF`;
  - тёмная тема: `#080B12` / `#131722` / `#FFFFFF` / `#8A92A6` / `#2A3446`;
  - радиусы карточек 10–12 dp, полей 10 dp, кнопок 14 dp, навигации 34 dp;
  - типографика: заголовок страницы 25 sp bold, секция 11 sp bold caps с межбуквенным интервалом, основной текст 13–15 sp, вторичный 11–12 sp;
  - отступы: поля страницы 20 dp, строки 14 dp;
  - движение: появление элементов снизу с затуханием, переход между страницами crossfade 280 мс, «пружинка» при нажатии.

## 4. Основные проблемы Desktop UI/UX

1. `main.kt`: окно не меняет размер, 1100×800 фиксировано.
2. `WelcomeScreen`: декоративный экран-заставка с 3-секундной анимацией и кнопкой «Next». Лишний шаг при каждом запуске.
3. `TransportScreen`: 4 карточки по центру огромного окна — лишний шаг до подключения.
4. `ConnectionConfigScreen`: форма, лог, статистика и кнопка в одной прокрутке. Автопрокрутка на старте блокирует ручную прокрутку (`verticalScroll(enabled = !locked)`). Пользователь пишет пути к файлам руками, выбора файла нет.
5. Нет hover-состояний, подсказок, контекстных меню и горячих клавиш; кликабельные `Box` без курсора-руки.
6. Статус «Connected» выставляется по строкам лога, а не по реальному состоянию сессии.
7. Настройки не сохраняются.

## 5. Предлагаемая структура нового Desktop UI

Окно с левым **сайдбаром** (Главная, Профили, Логи, Настройки; внизу статус соединения и версия). Сайдбар сворачивается в иконки при ширине меньше 900 dp.

- **Главная**: слева крупная кнопка подключения в стиле Android (кольца, цвет состояния, аптайм); справа карточки «Профиль» (выбор, смена), «Трафик» (↑/↓ скорость и объём), «Соединение» (режим, SOCKS5-адрес с копированием, активный транспорт, внешний IP), «Системный прокси» (переключатель). Ошибка — баннер с текстом и действием. На узком окне колонки складываются в одну.
- **Профили**: master-detail. Слева поиск и список (значок, имя, транспорты, бейдж «активен»). По наведению — быстрые действия, двойной клик подключает, правый клик открывает меню (подключить, изменить, QR, копировать ссылку, дублировать, удалить). Справа подробности или редактор. Кнопка «Добавить» открывает меню: вставить ссылку, из буфера, QR из файла, вручную.
- **Логи**: панель инструментов (поиск, фильтр уровня, автопрокрутка, копировать всё, очистить), моноширинный список с подсветкой тегов и выделением текста.
- **Настройки**: слева категории (Подключение, Системный прокси, Ядро OpenFlux, Интерфейс, О программе), справа их содержимое. Изменения сохраняются сразу.

## 6. Что переиспользуем из Android

- Модель профиля (`Profile`, `Transport`, `sessionTransportsJson`, `fromShare`) и формат `openflux://v1/`.
- Палитру светлой и тёмной тем, радиусы, типографику, иконки (векторные `ic_*.xml` переносятся в `composeResources` как есть), кнопку подключения с кольцами, карточку «ключ — значение», список настроек со значками в «пузырях», бейджи состояний.
- Логику состояний Android: подключено, подключение, остановка, ошибка, простой.

Из текущего Desktop: запуск и остановка процесса (включая `taskkill /T` для дерева процессов в Windows), `CaptchaBrowser` и `CaptchaIpc` (с тестами), `BinaryDownloader`.

## 7. Что нельзя переносить 1:1

- **Нижняя «таблетка»-навигация**: на десктопе удобнее боковая панель с подсказками и клавишами.
- **VpnService / туннель всего трафика**: в Windows нет аналога без драйвера Wintun и прав администратора. Замена — системный прокси Windows, его понимают браузеры и большинство программ.
- **DNS, MTU, фильтр приложений**: относятся только к TUN-туннелю Android. При SOCKS5 DNS резолвит нода, а приложения подключаются к прокси по своим настройкам.
- **Маршрутизация (домены в обход)**: в CLI ядра этого нет, так что пункт был бы декоративным.
- **QR-камера**: заменяется распознаванием QR из файла или картинки в буфере обмена.
- **Встроенный WebView для капчи**: в Compose Desktop его нет, остаётся изолированное окно Edge.
- **Мастер нод**: на Android он использует gomobile-мост и WebView. На десктопе нужен свой SSH-клиент и вход в Яндекс через Edge — отдельный этап.

## 8. План реализации

1. **Каркас проекта** `openfluxclient`: Gradle (версии как в OpenFluxDesktop), модули `shared` и `desktopApp`, Voyager, zxing, изменяемое по размеру окно с минимальным размером. Результат: запускающееся пустое окно.
2. **Дизайн-система** `ui/theme`: `AppColors` (светлая и тёмная), `AppTypography`, `AppSpacing`, `AppShapes`, `AppDimens`, `OpenFluxTheme`; компоненты `ui/components`: Button, IconButton, Card, Switch, TextField, Dialog, Tooltip, SidebarItem, StatusBadge, SectionLabel, KeyValueRow, ContextMenu. Иконки из Android.
3. **Домен и данные**: `Profile`, `TransportSpec`, `AppSettings`, `ConnectionState` (sealed), `ShareLink` (кодек `openflux://v1/`), `ProfileRepository` и `SettingsRepository` на JSON в `%APPDATA%/OpenFlux`. Юнит-тесты кодека и маппинга на ссылках, созданных ядром.
4. **Движок** `ConnectionManager` (jvmMain): сборка `--config` и аргументов, ключ во временном файле 0600, запуск и остановка ядра, IPC (статус, капча), внешний IP через SOCKS5, системный прокси Windows с восстановлением, выходная нода и разбор `--share`. Ядро: собранный из нашей ветки `openflux-windows-amd64.exe` поставляется с приложением; можно указать свой бинарник. Небольшое изменение ядра: периодическая отправка `MsgStatus` в IPC (подключено, байты, активный транспорт, аптайм).
5. **Навигация и оболочка**: Voyager `TabNavigator` для разделов, адаптивный сайдбар, горячие клавиши (Ctrl+1…4, Ctrl+V — импорт ссылки, Ctrl+Enter — подключить).
6. **Экраны**: Главная, Профили (список, редактор, импорт, QR), Логи, Настройки, диалог капчи, первый запуск (импорт или создание профиля).
7. **Проверка**: сборка, тесты, запуск и скриншоты при трёх ширинах окна, реальное подключение к нашей ноде через SOCKS5 и проверка внешнего IP, импорт ссылки и QR, системный прокси.

## 9. Архитектурные изменения

- Новый проект вместо правки старого: из старого переиспользуются только проверенные классы (запуск процесса, капча, IPC).
- Поток: `Compose UI → ScreenModel (Voyager) → ConnectionManager / ProfileRepository / SettingsRepository`. UI не трогает ни файлы, ни процесс.
- `commonMain`: модели, состояния, дизайн-система, экраны, интерфейсы сервисов. `jvmMain`: процессы, файлы, IPC, zxing, реестр Windows, deflate. Без expect/actual: реализации передаются через простой контейнер зависимостей в `main`.
- Состояние соединения — `sealed interface ConnectionState { Idle, Starting, Connected, Stopping, Failed }` вместо набора boolean.

## 10. Риски

- **Voyager 1.1.0-beta03 и Compose 1.11**: могут не совпасть бинарно. Проверю на первом этапе; при проблемах откачу Compose до совместимой версии.
- **Системный прокси**: если приложение упадёт, Windows останется с прокси, указывающим в пустоту. Защита: прежние значения сохраняются в настройках и восстанавливаются при следующем запуске.
- **IPC в Windows**: Unix-сокеты работают в Windows 10 1803+. Если сокет недоступен, приложение работает без статуса и капчи и сообщает об этом.
- **Ключ шифрования на диске**: хранится в профиле пользователя (`%APPDATA%`), доступ только у его учётной записи Windows. Шифрования DPAPI в этой версии нет.
- **Совместимость**: профили из `openflux://` должны давать тот же context, что ожидает нода (проверяется тестом на ссылке, созданной ядром).
