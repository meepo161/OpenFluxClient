# OpenFlux для компьютера

Настольный клиент OpenFlux на Kotlin Multiplatform и Compose Multiplatform
(навигация — Voyager). Визуально продолжает Android-приложение, но устроен
как настольная программа: боковая панель со свёрнутым режимом, список и
подробности рядом, контекстные меню, подсказки, горячие клавиши, полосы
прокрутки, три ширины окна.

Что умеет:

- профили из ссылок `openflux://` и QR-кодов (из файла или буфера), ручное
  создание и правка, в том числе Session с несколькими транспортами;
- подключение клиентом (SOCKS5 и HTTP-прокси на 127.0.0.1) и режим выходной
  ноды с QR-кодом для клиентов;
- живой статус от ядра по IPC: подключено или переподключается, скорость,
  объём, активный транспорт, внешний IP через туннель;
- системный прокси Windows с возвратом прежних настроек при отключении,
  выходе и после сбоя;
- проверки Яндекса в отдельном окне Edge, cookies уходят ядру (и ноде);
- мастер «Своя нода»: ставит отдельный канал на свой VDS по SSH, документ
  канала создаётся в браузере по умолчанию, потом мастер подключается через
  новую ноду и проверяет внешний IP, а профиль сохраняет или отдаёт QR-кодом;
- журнал с поиском, фильтром и скрытием ключей, трей, светлая и тёмная тема.

## Сборка и запуск

Нужен JDK 17.

```bash
./gradlew :desktopApp:run                 # запустить
./gradlew :shared:jvmTest                 # тесты
./gradlew :desktopApp:createDistributable # папка с OpenFlux.exe
./gradlew :desktopApp:packageMsi          # установщик
```

Встроенное ядро лежит в `desktopApp/resources/windows` и в git не входит.
Его собирает скрипт из ядра в [openfluxandroidfork](https://github.com/meepo161/openfluxandroidfork)
с IPC-статусом, `--http-proxy` и `--node-wizard` (помощник мастера нод: JSON
по stdin/stdout, SSH и установка через `provision`), нужен Docker:

```bash
scripts/build-core.sh ../path/to/openfluxandroidfork
```

В настройках можно указать и свой файл ядра.

## Устройство

- `shared/commonMain` — модели (`Profile`, `ShareConfig`, `CoreConfig`,
  `ConnectionState`), интерфейсы сервисов, дизайн-система
  (`ui/theme`, `ui/components`) и экраны: Главная, Профили, Логи,
  Настройки. Поток данных: экран → `ScreenModel` → сервисы.
- `shared/jvmMain` — хранение в `%APPDATA%\OpenFlux`, кодек ссылок,
  запуск ядра и IPC (`core/`), системный прокси Windows, буфер обмена и QR.
- `desktopApp` — окно, трей, горячие клавиши, упаковка.

Данные: `%APPDATA%\OpenFlux` (профили, настройки, cookies). Ключ и .conf
профиля пишутся в `runtime` только на время подключения. Сокет IPC живёт
во временной папке, потому что AF_UNIX в Windows работает не во всех
каталогах.

Горячие клавиши: Ctrl+1…4 — разделы, Ctrl+Enter — подключить или
отключить, Ctrl+N — новый профиль, Ctrl+I — импорт, Ctrl+S — сохранить,
Esc — отмена, Enter — главная кнопка диалога.
